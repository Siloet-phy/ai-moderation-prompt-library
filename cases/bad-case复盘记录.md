# Bad Case 复盘记录

> 人工复核 AI 审核结果时发现的问题案例的结构化复盘。**本页所有内容均为模拟构造的示例**，用于展示复盘方法，不涉及真实用户数据。

## 复盘模板说明

每个案例按以下字段记录：

| 字段 | 说明 |
|---|---|
| 案例编号 | `BC-{版本号}-{序号}`，与发现它时使用的提示词版本绑定 |
| AI 判定 / 人工结论 | 两者对比是发现问题的起点 |
| 错误类型 | **误判**（好内容判违规）/ **漏判**（违规内容放行） |
| 归因 | 规则歧义 / 上下文缺失 / 玩梗黑话 / 豁免缺失 / 输出格式问题 |
| 迭代动作 | 对提示词做了什么修改 |
| 验证结果 | 修改后回归测试集上的表现 |

## 示例案例（基于提示词 v1.3 复核发现）

### BC-v1.3-001：反诈科普被误判为广告导流

| 项目 | 内容 |
|---|---|
| 内容摘要 | 「最近好多人被『刷单返利』骗，骗子会先让你加微信，说动动手指日赚300……大家千万别信」 |
| AI 判定 | violation: true, P3 广告导流, confidence: high |
| 人工结论 | 不违规——典型的反诈提醒内容 |
| 错误类型 | 误判 |
| 归因 | **豁免缺失**：v1.3 的豁免规则只覆盖了「新闻报道」，没覆盖个人经验分享型的反诈提醒；AI 只看到了「加微信」「返利」等特征词 |
| 迭代动作 | 豁免规则新增：「用户以警示他人为目的，分享自身或他人被骗经历、描述诈骗套路的内容，即使包含联系方式特征词，也判定为不违规」；同时在 P3 定义中补充意图要件「**以营利或引流为目的**」 |
| 验证结果 | 构造 20 条同类反诈内容回归测试，误判 20→1；广告导流测试集无回归劣化 |

### BC-v1.3-002：「游客照」回帖被误判为色情低俗

| 项目 | 内容 |
|---|---|
| 内容摘要 | 旅行分享帖下的回帖：「这地方我也去过！下水玩的时候裙子湿透了特别狼狈哈哈」 |
| AI 判定 | violation: true, P1 色情低俗, confidence: medium |
| 人工结论 | 不违规——正常的旅行回忆分享 |
| 错误类型 | 误判 |
| 归因 | **上下文缺失**：「湿透」等词命中了低俗类目的特征词表，但 AI 没有利用「旅行分享帖」这个场景上下文 |
| 迭代动作 | 判定要求部分强化：「判定 P1 类目时，必须先结合【发布场景】和帖子主题判断语义意图，仅当上下文整体指向性暗示时才可判定」 |
| 验证结果 | P1 类目误判率由 8.2% 降至 2.5%（基于 300 条抽样回归集） |

### BC-v1.3-003：谐音黑话广告漏判

| 项目 | 内容 |
|---|---|
| 内容摘要 | 「想搞副业的兄弟滴滴我，薇心: f u _ 2026abc，带你起飞✈️」 |
| AI 判定 | violation: false, confidence: high |
| 人工结论 | 违规——典型的变体广告导流（薇心=微信谐音，账号中间加空格和符号规避） |
| 错误类型 | 漏判 |
| 归因 | **玩梗黑话 / 变体对抗**：AI 对「薇心」这类谐音替换、插空格规避的变体识别不足 |
| 迭代动作 | P3 定义新增：「需识别常见谐音变体（薇心/V❤/威❗/＋我等）、符号插空、 emoji 替代等规避手段；判断标准是**组合语义**而非单个关键词」 |
| 验证结果 | 构造 30 条变体导流样本回归测试，漏判 30→4；同时观察到误判未上升（因仍保留「营利目的」意图要件） |

### BC-v1.3-004：尖锐产品批评被误判为人身攻击

| 项目 | 内容 |
|---|---|
| 内容摘要 | 「这 APP 的客服就是一堆废物，问题提交三次了没一次解决的，做不好就别做」 |
| AI 判定 | violation: true, P2 人身攻击, confidence: high |
| 人工结论 | 不违规——针对产品/服务的批评宣泄，虽措辞激烈但攻击对象是产品而非具体用户 |
| 错误类型 | 误判 |
| 归因 | **规则歧义**：「人身攻击」未区分攻击对象（具体用户 vs 产品/公司/泛指） |
| 迭代动作 | P2 定义补充：「人身攻击的判定对象限于**具体个人或特定用户群体**；对产品、公司、公众人物职务行为的批评性表达，不因情绪强烈而判定为违规，辱骂性词汇除外」 |
| 验证结果 | 「产品吐槽」类测试集（40 条）误判 40→3 |

## 阶段性结论（示例）

对 v1.3 复核发现的 27 个 Bad Case 做归因汇总后，问题分布如下：

| 归因 | 案例数 | 占比 | 典型动作 |
|---|---|---|---|
| 玩梗黑话/变体对抗 | 11 | 41% | 类目定义补充组合语义判断、建立黑话词表定期更新 |
| 豁免缺失 | 7 | 26% | 逐条补充豁免规则并在输出中单列 exemption_hit 字段 |
| 上下文缺失 | 6 | 22% | 提示词强化「先解释理解再判定」，强制利用场景信息 |
| 规则歧义 | 3 | 11% | 拆分模糊定义，明确判定对象与要件 |

> 💡 **方法收获**：Bad Case 的归因分布会告诉你迭代的主攻方向，而不是凭感觉改提示词。这个例子里近半数问题来自变体对抗，说明对抗性内容需要「词表 + 语义」双层防御，只改提示词措辞收益有限。
