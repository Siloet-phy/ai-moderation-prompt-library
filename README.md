# AI 内容审核提示词库（ai-moderation-prompt-library）

> 把「社区规范」翻译成「AI 可执行的审核指令」：一套包含方法论、提示词模板、Bad Case 复盘与评估迭代的完整实践记录。

## 🎯 项目背景

在参与社区内容审核相关项目时（AI 辅助社区治理方向），我发现自己每天重复的核心工作其实是同一件事：

**社区规范是人写的、给人看的；但 AI 需要的是结构化、无歧义、可判定的指令。**

这个仓库沉淀的就是这个「翻译」过程的方法论和素材：

- ✅ 如何把模糊的规范条文（如「禁止恶意攻击他人」）拆解为 AI 可判定的具体条件
- ✅ 一套可直接复用的审核提示词模板（覆盖常见违规类目）
- ✅ 如何通过人工复核 AI 结果发现 Bad Case，并反哺提示词迭代
- ✅ 如何定义和计算误判率、漏判率，用数据驱动迭代

## 🔄 核心方法论：五步迭代闭环

```
① 规则结构化 → ② 提示词编写 → ③ AI 试运行 → ④ 人工复核 → ⑤ Bad Case 分析与迭代
      ↑                                                              │
      └──────────────────────────────────────────────────────────────┘
```

### ① 规则结构化：把「规范」变成「判定条件」

社区规范通常是「原则性」的，直接丢给 AI 效果很差。我的做法是把每条规范拆成四要素：

| 要素 | 说明 | 示例（以「禁止广告导流」为例） |
|---|---|---|
| **行为主体** | 谁在做这件事 | 任何发帖/回帖用户 |
| **具体行为** | 客观可观察的动作 | 发布联系方式、外部链接、优惠信息引导站外交易 |
| **判定条件** | 满足什么条件算违规 | 出现微信号/QQ号/二维码/「加我」类引导语，且无正当语境 |
| **豁免情形** | 哪些看似违规但应放行 | 用户讨论「如何防止被骗」时提到诈骗套路中的联系方式特征 |

> 💡 **最容易忽略的是「豁免情形」**——误判（把好内容判违规）对社区氛围的伤害往往比漏判更大，因为它伤害的是正常用户。

### ② 提示词编写

见 [`prompts/审核提示词模板.md`](prompts/审核提示词模板.md)，核心设计原则：

1. **先给角色和任务边界**，再给类目定义，最后给输出格式——顺序影响准确率
2. **类目之间互斥**，给出多类目并发时的优先级规则
3. **强制输出结构化结果**（JSON），包含判定依据，方便人工复核和后续统计
4. **要求置信度分级**，让 AI 「不确定」的内容进入人工队列，而不是硬给结论

### ③ 试运行 + ④ 人工复核

- 用历史已定性的内容（人工审核过的存量数据）做试运行，先看 AI 判定与人工结论的一致率
- 上线后对 AI 结果做**分层抽样复核**（方法见 [`metrics/评估与迭代.md`](metrics/评估与迭代.md)）

### ⑤ Bad Case 分析与迭代

每次复核发现的误判/漏判，按统一模板归因（规则歧义 / 上下文缺失 / 玩梗黑话 / 立场表达误伤），再针对性改提示词。示例见 [`cases/bad-case复盘记录.md`](cases/bad-case复盘记录.md)。

## 📊 我的核心收获

1. **AI 审核的本质是人机分工**：AI 负责「高置信度的明确违规」，人负责「模糊地带和申诉」，提示词的质量决定了这条分界线画在哪里
2. **误判和漏判的代价不对等**：不同业务场景下应该主动选择「宁严勿漏」或「宁松勿误」，并把这个倾向写进提示词
3. **迭代要有数据支撑**：「感觉不准」没有意义，必须落到「哪类目、什么错误类型、占比多少、改动后是否收敛」
